# MERN Cloud Disk

Веб-приложение «облачный диск» в духе Google Drive и Яндекс.Диска: пользователь регистрируется, хранит файлы в иерархии папок, загружает и скачивает их, ищет, сортирует и управляет профилем. Проект построен на стеке MERN (MongoDB, Express, React, Node.js) на основе учебного курса Ulbi TV и существенно доработан: безопасность загрузки и скачивания, управление памятью на сервере, навигация по адресной строке.

## 1. Назначение и возможности

Приложение решает задачу личного файлового хранилища с веб-интерфейсом. Каждый пользователь работает только со своими файлами и ограничен дисковой квотой (по умолчанию 10 ГБ).

**Возможности для пользователя**

- **Регистрация и вход.** Валидация e-mail и пароля, пароли хранятся в виде хэшей (bcrypt), сессия на JWT. Токен проверяется при каждом запуске приложения.
- **Иерархия папок.** Создание папок, вход двойным кликом, **хлебные крошки** над списком. У каждой папки собственный адрес `/folder/:id`, корень диска — `/`. Работают кнопки «назад/вперёд» браузера, обновление страницы (F5) и прямые ссылки.
- **Загрузка файлов.** Кнопка «Загрузить файл» (можно выбрать несколько) и перетаскивание файлов мышью в окно браузера. Панель загрузок показывает прогресс и ошибки каждого файла.
- **Скачивание.** Браузер принимает файл потоком, с менеджером загрузок и докачкой.
- **Удаление** файлов и папок (папка удаляется вместе со всем содержимым) с подтверждением.
- **Поиск** по имени среди всех файлов и папок пользователя с задержкой ввода (debounce). Найденную вложенную папку можно открыть, цепочка крошек восстанавливается.
- **Сортировка** по имени, дате и размеру в обе стороны. Папки всегда остаются выше файлов, имена сравниваются «естественно» (`file2` раньше `file10`).
- **Квота.** Полоса «Использовано X из Y ГБ», пересчитывается после загрузки и удаления.
- **Профиль и аватар.** Меню в шапке: загрузка, замена и удаление аватара (JPEG, PNG, WebP до 2 МБ), выход.

## 2. Технологический стек

| Слой | Технологии |
|---|---|
| Frontend | React 19, Vite, React Router 7, Redux 5 + redux-thunk, axios |
| Backend | Node.js (ES-модули), Express 5, express-fileupload, express-validator |
| База данных | MongoDB Atlas, Mongoose 9 |
| Аутентификация | JWT (jsonwebtoken), bcryptjs |
| Конфигурация | пакет `config`, переменные окружения через `dotenv` |

**Безопасность и хранение:**

- JWT авторизации (срок 1 час) и отдельные **короткоживущие HMAC-подписанные токены скачивания** (60 секунд, один файл одного пользователя).
- Строгая проверка **сигнатур** (магических байтов) для аватаров.
- Защита от выхода за пределы папки пользователя (path traversal).
- Файлы лежат на диске сервера, в MongoDB хранятся только метаданные (имена, пути, размеры, владельцы, связи).

## 3. Архитектура и структура репозитория

```
.
├── client/                      # SPA на React
│   └── src/
│       ├── actions/             # асинхронные действия (thunk): файлы, пользователь
│       ├── reducers/            # Redux: user, files, upload
│       ├── components/
│       │   ├── authorization/   # формы входа и регистрации
│       │   ├── navbar/          # шапка, аватар, меню профиля
│       │   └── disk/            # Disk, Breadcrumbs, FileList, File, Popup,
│       │                        # DiskSpace, Uploader
│       ├── utils/               # sortFiles, dropFiles, sizeFormat, routes
│       └── config.js            # адреса сервера (VITE_SERVER_URL)
└── server/
    ├── index.js                 # точка входа: .env, проверка секретов, БД, запуск
    ├── app.js                   # сборка Express-приложения (без БД и порта)
    ├── env.js                   # загрузка .env (импортируется первым)
    ├── routes/                  # описание маршрутов
    ├── middleware/              # auth.middleware, upload.middleware
    ├── controllers/             # fileController, userController
    ├── services/                # fileService: пути, токены скачивания, операции с диском
    ├── models/                  # User, File (Mongoose)
    ├── utils/                   # imageType, tempFiles, userDto
    ├── config/                  # default.json, custom-environment-variables.json
    └── storage/                 # данные во время работы (не в git)
        ├── files/<userId>/...   # файлы пользователей
        ├── avatars/             # аватары
        └── tmp/                 # временные файлы загрузки
```

**Слои на сервере:** маршруты (`routes`) → промежуточные обработчики (`middleware`: авторизация, разбор загрузки) → контроллеры (HTTP-логика, проверки) → сервисы и утилиты (диск, токены, форматы) → модели (MongoDB). Сборка приложения вынесена в `app.js`, поэтому его можно запускать без базы и порта.

**Модель данных**

- `User`: `email` (уникальный), `password` (хэш), `diskSpace`, `usedSpace`, `avatar` (имя файла).
- `File`: `name`, `type` (`dir` для папок, расширение для файлов), `size`, `path` (относительный путь от корня пользователя), `parent`, `user`, `date`.

**Основные маршруты API**

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/registration`, `POST /api/auth/login`, `GET /api/auth/auth` | регистрация, вход, проверка токена |
| `POST` / `DELETE /api/auth/avatar` | загрузка и удаление аватара |
| `GET /avatars/<имя>` | публичная раздача аватаров (статика) |
| `GET /api/files?parent=` | содержимое папки |
| `POST /api/files` | создание папки |
| `POST /api/files/upload` | загрузка файла |
| `GET /api/files/download-link?id=` → `GET /api/files/download?token=` | скачивание в два шага |
| `DELETE /api/files?id=` | удаление файла или папки |
| `GET /api/files/search?search=` | поиск по имени |
| `GET /api/files/breadcrumbs?id=` | цепочка родителей папки |

## 4. Ключевые технические решения

### 4.1. Память сервера: временные файлы вместо буфера в RAM

`express-fileupload` по умолчанию копит загружаемый файл целиком в памяти процесса. Поэтому загрузка включена в режиме `useTempFiles: true`: данные пишутся на диск по мере приёма в `server/storage/tmp`, а затем файл **переименовывается** на место (папка `tmp` лежит рядом с хранилищем, на том же диске, поэтому перенос мгновенный).

- Лимит размера одного файла (`maxUploadSize`, по умолчанию 2 ГБ) применяется на лету: лишнее на диск не пишется, ответ 413.
- Временные файлы удаляются при **любом** исходе (успех, дубликат, нехватка места, ошибка валидации, ошибка БД, обрыв соединения).
- «Осиротевшие» файлы (падение сервера, оборванная загрузка) подчищает фоновая задача при старте и каждые 30 минут.
- Разбор файла подключён **после** проверки авторизации: неавторизованный запрос ничего не буферизует и не пишет на диск.

**Измерение** (тестовый стенд, файл 400 МБ, память процесса сервера измерялась снаружи): со старым режимом пик достигал **900 МБ** и не возвращался, с временными файлами пик **179 МБ** с возвратом к 102 МБ, при этом загрузка шла примерно вдвое быстрее. Прирост памяти не зависит от размера файла.

### 4.2. Потоковое скачивание

Браузерное скачивание не умеет передавать заголовок `Authorization`, а скачивание через `axios` и `Blob` собирает файл целиком в памяти вкладки. Решение в два шага:

1. Клиент запрашивает `download-link` (с обычной авторизацией) и получает токен на 60 секунд.
2. Браузер сам переходит по `download?token=…`; сервер читает файл с диска потоком (`res.download`), клиент пишет его на диск. Поддерживается докачка (`Range`).

Токен подписан **отдельным ключом**, выведенным из секрета JWT через HMAC. Поэтому токен скачивания не проходит как обычный Bearer-токен, а обычный токен не подходит для ссылки. Токен привязан к одному файлу и одному пользователю. На файле 400 МБ память сервера выросла лишь на ~70 МБ и вернулась к исходной.

### 4.3. Безопасность загрузки

- **Path traversal.** Все пути на диске строятся через `FileService.getPath()`: путь нормализуется и проверяется, что он остаётся внутри папки пользователя (иначе ошибка). Имена папок с разделителями и запрещёнными символами отклоняются, имя загружаемого файла очищает парсер multipart. Это важно, потому что удаление папок рекурсивное.
- **Проверка сигнатур у аватаров.** Формат определяется по первым байтам файла (JPEG, PNG, WebP), а не по расширению и `mimetype`, которые выбирает клиент. Текст, HTML со скриптом, SVG, GIF и исполняемые файлы под видом `.png` отклоняются. Лимит 2 МБ, файл больше лимита не попадает в память целиком.
- **Имена аватаров** генерирует сервер: `<id пользователя>-<16 случайных символов>.<расширение>`. Имя меняется при каждой загрузке (адрес не остаётся в кэше), старый файл удаляется; перед удалением имя проверяется по шаблону, чтобы подменённое значение в БД не привело к удалению постороннего файла.
- **Раздача аватаров** как статики с заголовками `X-Content-Type-Options: nosniff` и долгим кэшем (`immutable`).
- **Квота.** Занятое место меняется атомарно (`$inc`), параллельные загрузки не затирают значения друг друга. Если запись в БД после переноса файла не удалась, файл удаляется из хранилища.
- **Секреты** (строка подключения к БД и ключ JWT) вынесены в `.env`; без них сервер отказывается стартовать.

### 4.4. Умный роутинг: состояние папок привязано к адресной строке

Текущая папка определяется адресом `/folder/:id`, адрес является **единственным источником правды**. Любое действие пользователя (двойной клик, крошка-ссылка, «назад/вперёд», F5, прямая ссылка) только меняет URL, а состояние Redux подстраивается под него в одном месте (`syncDir`) от дешёвого к дорогому: уже там → обрезать путь (папка выше по пути) → добавить дочернюю папку из загруженного списка → запросить цепочку у сервера.

- **F5 и прямые ссылки.** Пока токен проверяется, маршруты не строятся: иначе приложение считало бы пользователя неавторизованным и заменило адрес на `/login`. Пока папка из адреса не определена, список не загружается и загрузки не принимаются (иначе файлы ушли бы в корень).
- **Защита от гонок.** Устаревшие ответы списка, поиска и синхронизации пути игнорируются по номеру запроса.
- **Неверный адрес** (несуществующий или некорректный `id`) ведёт в корень с сообщением, при этом запись истории заменяется и «назад» не возвращает на битый адрес.
- Удаление папки, в которой вы находитесь, переносит на уровень выше.

### 4.5. Надёжность регистрации (откат при сбоях)

Регистрация не оставляет «полузарегистрированных» пользователей. Сначала создаётся корневая папка пользователя на диске, затем запись в БД. Если сохранение в БД не удалось, созданная папка удаляется, а клиент получает ошибку со статусом 500. Если недоступно хранилище, пользователь в БД не создаётся и регистрацию можно повторить.

## 5. Развёртывание и запуск

**Требования:** актуальная LTS-версия Node.js (проект разрабатывался и проверялся на Node.js 24), аккаунт MongoDB Atlas (или любая MongoDB), Git (по желанию).

**1. Установка зависимостей**

```bash
cd server && npm install
cd ../client && npm install
```

**2. Настройка окружения.** Скопируйте `server/.env.example` в `server/.env` и заполните значения. Файл `.env` в репозиторий не попадает.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `DB_URL` | строка подключения MongoDB (обязательна) | — |
| `JWT_SECRET` | секрет подписи JWT, длинная случайная строка (обязателен) | — |
| `PORT` | порт сервера | `5000` |
| `FILE_PATH` | папка файлов пользователей | `storage/files` |
| `AVATAR_PATH` | папка аватаров | `storage/avatars` |
| `TEMP_PATH` | папка временных файлов загрузки | `storage/tmp` |
| `MAX_UPLOAD_SIZE` | максимальный размер файла, байт | `2147483648` (2 ГБ) |

Пути указывайте в папке, куда у процесса есть право записи (не в `C:\Users` и не в корень диска), а `TEMP_PATH` лучше держать на том же диске, что и `FILE_PATH`. Сгенерировать секрет:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

**3. Запуск**

```bash
# терминал 1: сервер (http://localhost:5000)
cd server
node index.js

# терминал 2: клиент (http://localhost:5173)
cd client
npm run dev
```

Если порт 5000 занят, укажите другой адрес сервера для клиента в `client/.env.local`: `VITE_SERVER_URL=http://localhost:5090` (и `PORT=5090` в `server/.env`).

**Проверка качества кода клиента:**

```bash
cd client
npm run lint
npm run build
```

## 6. Ограничения и возможное развитие

Честно о текущем состоянии проекта:

- Автоматических тестов в репозитории нет. Логика проверялась отдельными сценариями на тестовом стенде (подменённые модели, реальный HTTP, измерения памяти); их стоит оформить как набор тестов (например, Vitest или Node test runner).
- Папки нельзя загружать целиком (перетаскивание папок отклоняется с сообщением).
- Аватары публичны по прямой ссылке (имя непредсказуемо, но это не приватное хранилище).
- JWT хранится в `localStorage`, нет refresh-токенов и механизма отзыва; пароль ограничен длиной 3–12 символов (стоит усилить правила).
- Нет общего доступа к файлам и ссылок «поделиться», нет корзины и переименования.
- Рекомендуемые следующие шаги: CI с линтером и тестами, Docker-образы, хранение файлов в объектном хранилище (S3-совместимом), предпросмотр файлов.
